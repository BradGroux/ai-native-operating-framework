# ADR-007 — Shared operating memory

- **Status:** accepted
- **Date:** 2026-07-30
- **Owner:** Brad Groux

## Question

Should the AI-Native Operating Framework require organizations to define how
operating knowledge is captured, grounded, shared, recalled, governed, and
improved, and if so, does that require a particular memory technology or an
additional framework concern?

## Decision

The framework includes **shared operating memory** as a cross-cutting business
capability.

Shared operating memory is the controlled, durable body of sources, context,
decisions, work state, evidence, handoffs, and lessons that allows authorized
people and AI to continue, verify, and improve work over time.

Organizations applying the framework establish a proportionate shared
operating-memory practice or show how existing knowledge, records, and work
management practices satisfy the same business requirements. The practice
defines capture, provenance, authority, access, sharing, recall, retention,
correction, recovery, and improvement.

The capability is defined in the
[shared operating memory standard](../framework/shared-operating-memory-standard.md).
It supports the existing concerns of Work, Control, Assurance, and Learning. It
does not create a seventh concern or a ninth SOP content requirement.

The framework does not prescribe Git, Markdown, file systems, document
platforms, knowledge bases, databases, retrieval systems, model memory,
repository layouts, or machine-specific representations. Examples may use
those technologies as explicit implementation choices without making them
framework requirements.

## Consequences

- Material operating context does not depend solely on individual
  recollection, conversation history, or an AI model's temporary context.
- SOPs continue to identify their own authoritative sources, recorded state,
  evidence, handoffs, and maintenance expectations.
- A shared operating-memory practice supplies consistent cross-process rules
  for preserving and finding those materials.
- People and AI use the same approved operating memory under the same governing
  access, authority, privacy, retention, and quality rules, with permissions
  appropriate to each participant's role.
- Stored information does not become authoritative merely because it is
  durable, searchable, summarized, or generated by AI.
- Existing systems of record, records-management programs, data governance,
  privacy, security, and professional controls retain their authority.
- Organizations can adopt the standard without replacing sound existing
  repositories or workflows.

## Alternatives Considered

### Leave operating memory implicit

Rejected. The existing framework requires sources, state, evidence, handoffs,
and learning, but leaving the cross-process memory practice implicit invites
fragmented repositories, inaccessible context, unsupported summaries, and
lessons that never reach maintained standards.

### Prescribe a Git-and-Markdown memory system

Rejected as a framework requirement. Version-controlled documents are a useful
implementation example, but they do not by themselves establish authority,
access, retention, privacy, review, or records control and will not fit every
organization.

### Add a seventh framework concern

Rejected. Shared operating memory expresses and connects Work, Control,
Assurance, and Learning rather than introducing a separate subject around the
work.

### Add a ninth SOP content requirement

Rejected. The existing requirements already cover sources, recorded state,
handoffs, controls, evidence, and maintenance. The missing need is a
cross-process standard explaining how those elements remain durable and shared.

### Rely on chat history or model memory

Rejected. Participant memory and temporary model context are useful working
inputs but are not sufficient organizational records, do not reliably preserve
sources or authority, and may be unavailable to the next participant.

## Dissent and Uncertainty

No material dissent is recorded. Organizations may use different terminology,
combine this capability with knowledge or records management, or distribute it
across several controlled systems. Practical use may reveal where the standard
needs stronger distinctions among operational knowledge, authoritative
records, and temporary working context.
