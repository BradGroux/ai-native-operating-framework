# Tickets: AI-Native Operating Framework Stage 2

These tickets build the documentation package defined in the
[Stage 2 specification](../specifications/stage-2.md).

> **Later extension:** Tickets 01 through 14 govern the original Stage 2
> package. Shared operating memory was accepted later under a separate
> [extension specification](../specifications/shared-operating-memory-extension.md).
> These tickets are retained without retroactively changing their acceptance
> scope.

Work the frontier: begin any ticket whose blockers are complete. Each example is
an independently reviewable artifact.

## Ticket 01 — Core framework package

**What to build:** Give a reader a coherent entry point, charter, operating
framework, and approved vocabulary that explain the framework without requiring
technology or product knowledge.

**Blocked by:** None — can start immediately.

- [x] The charter states the mission, scope, commitments, non-goals, openness,
      stewardship, and amendment path.
- [x] The operating framework defines the six business concerns and how they
      apply to existing business lifecycles.
- [x] The glossary uses the same approved language.
- [x] Navigation connects the core documents, decisions, and delivery plan.
- [x] No core document introduces a technology specification, universal
      lifecycle, or mandatory document template.

## Ticket 02 — SOP standard and maintenance method

**What to build:** Let an organization create, assess, approve, use, and improve
an SOP using the eight content requirements and six maintenance activities.

**Blocked by:** Ticket 01 — Core framework package.

- [x] The SOP standard defines all eight required content areas.
- [x] The standard permits domain-appropriate layouts.
- [x] The method defines Understand, Document, Validate, Approve, Use, and
      Improve.
- [x] Practical review checklists cover normal, exceptional, and failure cases.
