# Security and Sensitive-Disclosure Policy

## Purpose

This policy provides a private route for reporting credentials, personal or
confidential information, unsafe publication, malicious repository behavior, or
another security-sensitive condition affecting this repository.

It does not replace the [Code of Conduct](CODE_OF_CONDUCT.md), framework
[contribution SOP](CONTRIBUTING.md), or appropriate professional and
organizational incident-response procedures.

## Supported Versions

The latest approved release and the current `main` branch receive
security-sensitive corrections. Superseded versions may be corrected only when
the founding steward determines that the consequence warrants it.

## Report Privately

Do not place sensitive details, credentials, personal information, private
evidence, or exploit instructions in a public issue, pull request, discussion,
or appeal.

Use
[GitHub private vulnerability reporting](https://github.com/bradgroux/ai-native-operating-framework/security/advisories/new)
when it is available. If it is unavailable, use a private contact route listed
on the [`@BradGroux`](https://github.com/BradGroux) GitHub profile.

If neither route is immediately available, submit the
`Private sensitive-disclosure contact request` issue form without credentials,
names, evidence, contact details, exploit instructions, or other sensitive
information. Monitor that public request while the founding steward enables or
identifies a repository-controlled private route. The public request is not
itself a private reporting channel. If a private route cannot be established,
retain the sensitive material safely and do not post it publicly.

Include only what is necessary to establish:

- the affected repository content or release;
- the nature and likely consequence of the condition;
- whether sensitive material may already be public;
- safe reproduction or verification steps, when applicable;
- containment already performed;
- and a private way to continue the report.

## Response and Disclosure

The founding steward or delegated maintainer will:

1. acknowledge and contain the report through a private channel;
2. preserve necessary evidence without unnecessarily copying sensitive
   material;
3. assess affected content, versions, derivatives, and recipients;
4. involve the appropriate privacy, security, legal, records, safety, or other
   authority when needed;
5. correct, withdraw, rotate, or otherwise contain affected material under the
   responsible authority;
6. verify the correction and document the release effect; and
7. coordinate any public disclosure so it does not increase harm.

No response-time guarantee, bug bounty, confidentiality contract, or safe-harbor
term is created by this policy. Reporters and maintainers remain responsible for
applicable law, authorization, professional duties, and organizational policy.

## Framework Questions

Sanitized questions or proposals about framework meaning may use the normal
[contribution process](CONTRIBUTING.md). A concern becomes a private security
matter when public handling could expose sensitive information, enable harm, or
interfere with containment.
